# Writing standards.md

What a good piece of this person's work has in it, so a skill can produce one without being told each time. Shape, not content: nothing a client said or paid is copied into this file.

## Read

Each piece on the bench (or in the connected folder the person pointed at). For each, note:

- What it is (proposal, report, deck, letter, update) and who it was for (a type, not a name).
- Length in pages or slides.
- The sections, in order, and what each does.
- What is on page one or slide one.
- How it opens (the first sentence's job) and how it closes (the ask, the next step, the sign-off).
- How prices, numbers and dates are shown.
- Tables, charts, images: how many and what for.
- What the person clearly cares about: the thing that is done carefully every time.

Where the pieces disagree, prefer the most recent, and say so.

## Write

One section per type of document, each a checklist Claude can follow:

```
# Standards

Written by capture on <date> from: <the pieces, by type>.

## Proposal
- Length: <n> pages. Word, from the letterhead template.
- Page one: <what is on it: e.g. the client's problem in two lines, what we will do, the price>.
- Sections, in order: <list>.
- Opens with: <e.g. the client's words for the problem, from the call>.
- Price: <how shown: a table, inc or ex tax, fixed or range>.
- Closes with: <e.g. the next step and a date, no hard sell>.
- Always: <two or three things that are never missing>.
- Never: <two or three things this person does not do>.

## <Next type>
...
```

Add a short "Any document" section at the end for the habits that apply to all of them (fonts and colours come from brand.md; no filler openers; dates in this format; units on every number; whatever the work shows).

## If there is only one piece

Write the standard for that type and say the others will follow when there is an example. Do not invent a standard for a document type you have not seen.
